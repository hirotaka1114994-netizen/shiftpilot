### 2026-11-09 自動作成の実装（最優先目標へ変更）
**調査結果**
- 以前の「最適化済み勤務案を読み込む」ボタンは計算をしていなかった。2026年11月分の固定データを貼り付けるだけで、他の月では動かず、希望休も消えた。計算に使った Python のプログラムはリポジトリにない。
- 条件の矛盾：編集画面の「月末日は夜勤不可」と、検証の「毎日夜勤2名以上」が両立せず、条件を満たす勤務表は存在しなかった（固定データは月末日に夜勤3名を入れていた）。→ 利用者の判断で「月末日も夜勤を入れる」に決定（要件 A-1）。

**完了したこと**
- `index.html`：自動作成の処理 `autoGenerate`（条件を満たす配置を日ごとに探索し、行き詰まったら戻ってやり直す）を追加。ボタン名を「✦ 自動作成」に変更し、表示中の月で計算するようにした。希望休は維持する。成立しない場合は、事前チェックで日付と理由（不足人数・不足資格）を表示し、勤務表は変更しない。
- `index.html`：月末日の夜勤を編集で設定できるようにした（A-1）。見出し・説明文・「この試作品の範囲」を実態に合わせて更新。固定データは削除し `tests/fixtures/sample-2026-11.json` に移した。
- `tests/rules-check.cjs`：要件から独立に書いた条件の検査プログラム。
- `tests/generate.cjs`：自動作成の検証テスト。
- `tests/smoke.cjs`：自動作成と月末日夜勤の確認に更新。

**確認結果**
- `node tests/generate.cjs`：8/8項目OK。

  - 4つの月（30日・31日・28日・29日）× 希望休0・10・25件 × 3パターン＝36通りすべてで作成でき、独立した検査とアプリの validate() の両方で違反0件。1回あたり最長約0.1秒。

### 2026-11-09 スマホ表示の修正（既知の問題 #1）
**完了したこと**
- 原因：画面幅950px以下の段組み指定 `grid-template-columns:1fr` が、勤務表の最小幅（1000px）に合わせて広がっていた。スマホではページ全体が約1200pxになり、約3分の1に縮小表示されて文字が極端に小さくなっていた。
- 修正：`index.html` の同じ指定を `minmax(0,1fr)` に変更（1か所のみ）。勤務表は枠の中で横スクロールする。勤務ルール・計算・保存の処理は変更なし。

**確認結果**
- `node tests/smoke.cjs`：15/15項目OK（修正前は14/15）。
- ページ幅＝画面幅を確認：iPhone SE（320px）、iPhone 13（390px）、Pixel 7（412px）、タブレット（820px）、PC（1366px）。
- 文字の重なり・はみ出しを自動判定：上記すべての幅で0件（勤務表の外、勤務表の各マス、編集ダイアログ）。修正前も文字同士の重なりは検出されず、問題はページの広がりと縮小表示だった。
- スクリーンショットを目視確認：スマホ（上部・勤務表・横スクロール後・編集ダイアログ・希望休欄）、タブレット、PC。
- 未確認：実機のスマホ（iPhone Safari・Android Chrome）。確認はパソコン上のブラウザ（Chromium）でスマホを再現したもの。Safari 固有の表示差は未確認。

**残る問題**：既知の問題 #2〜#4。

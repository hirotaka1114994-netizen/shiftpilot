# 不具合調査

## 1. 情報の整理
- 利用者の報告から「どの画面で」「何をしたら」「何が起きたか」「本来どうなるべきか」を整理する。
- 足りない情報があれば、答えやすい形（選択肢つき）で1回にまとめて質問する。端末（スマホ／PC、機種）も確認する。
- 「本来どうなるべきか」が `docs/requirements.md` の確定条件にない場合は、**未確定**として扱い、決めつけない。

## 2. 再現
- `tests/smoke.cjs` を参考に、Playwright（ブラウザ自動操作）で同じ操作を再現する。スマホの報告なら `devices['iPhone 13']` などで再現する。
- 再現できたら、その操作をテスト項目として `tests/smoke.cjs` に追加する（この時点ではNGになることを確認）。
- 再現できない場合は、試した条件を記録して利用者に報告する。

## 3. 原因の特定
- `index.html` の該当処理を読み、原因を1〜2文で説明できるまで調べる。
- `docs/progress.md` の既知の問題と同じかどうか確認する。

## 4. 修正
- 修正が小さく、要件を変えない場合はそのまま修正する。
- 次の場合は**修正前に利用者へ確認**する：勤務ルール・検証基準・自動処理の動きが変わる／保存データの形が変わる（既存データが消える可能性）／見た目が大きく変わる。
- 確認するときは「原因」「選択肢（2〜3案）と、それぞれの現場での影響」「おすすめ」を示す。

## 5. 確認と記録
- `node tests/smoke.cjs` を実行し、追加したテストがOKになり、ほかの項目が悪化していないことを確認する。
- 画面に関わる場合は `/ui-check` の手順でスクリーンショットも確認する。
- `docs/progress.md` を更新する（既知の問題から削除し、作業記録へ）。

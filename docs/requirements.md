## B. 現在のコードの動作（未確定・承認待ち）

2026-11-09 時点の `index.html` から読み取ったもの。**承認済みの要件ではありません。**

### B-1. 前提
- 対象：14名の架空スタッフ（A〜N）、初期表示は2026年11月。
- スタッフ属性：リーダー（A〜G）、運転可（A〜K）、夜勤指導中の新人（L・M）、日勤専従（N）。
- 勤務区分：日（日勤）／△（夜勤入り）／×（夜勤明け）／休（公休）／有（有休）。
- 保存先：端末のブラウザ内（localStorage）のみ。月ごとに別保存。

### B-2. 自動処理
- 夜勤（△）を入れると翌日が自動で夜勤明け（×）になる。
- 夜勤を別の区分に変えると、翌日の×は休に戻る。
- 日勤専従者には夜勤を入れられない。（月末日の夜勤禁止は 2026-11-09 に廃止：A-1）
- 希望休のマスは編集できない（先に解除が必要）。
- 希望休を登録すると、その日は休になり、前日が夜勤なら前日も休に変わる。

### B-3. 検証ルール（違反を「要確認」として表示）
自動作成はこれらを**すべて必ず守る条件**として扱う（緩和しない）。どれが本当に必須かは未確定。

| ルール | 現在の基準値 | 状態 |
|---|---|---|
| 日勤人数 | 4名以上（「目安」と表示） | 未確定 |
| 日勤の運転可 | 2名以上 | 未確定 |
| 日勤リーダー | 1名以上 | 未確定 |
| 夜勤人数 | 2〜3名 | 未確定 |
| 夜勤リーダー・運転可 | 各1名以上 | 未確定 |
| 新人が夜勤に入る日 | 夜勤3名配置 | 未確定 |
| 新人同士の夜勤 | 同じ日に2名以上は不可 | 未確定 |
| 夜勤明けの翌日 | 日勤は不可 | 未確定 |
| 連続夜勤 | 3回連続（1日おき）は不可 | 未確定 |
| 4連続日勤の直後の夜勤 | 不可 | 未確定 |

### B-4. その他の機能
- 自動作成（2026-11-09 追加）：表示中の月について、B-3 の全ルールと希望休を守る勤務表をブラウザ内で計算する。どの月でも動く。成立しない場合は、日付と理由を表示し、勤務表は変更しない。
  - 守る条件：B-3 の全ルール、希望休は休、希望休の前日は夜勤にしない（希望休の日が明けにならないように）、日勤専従は夜勤なし。
  - 目安（必須ではない）：夜勤・日勤の回数の偏りと連続勤務を少なくする。
  - 以前の「最適化済みサンプル読み込み」（2026年11月の固定データ）は廃止。データは `tests/fixtures/sample-2026-11.json` に保存し、検査プログラムの確認に使用。
- CSV書き出し（Excelで開ける文字コード）。
- 「初期化」で、その月を機械的な初期パターンに戻す。
